# 抓取限制：搜索、AI训练和Agents

主题后台开关是拒绝声明，不是服务器防火墙。默认关闭；开启后覆盖本主题渲染的HTML，关闭不会撤销Halo系统自身的SEO屏蔽。

1. 更新主题并重载配置，在“抓取与AI使用限制”开启声明开关。Halo系统“设置 → SEO设置 → 屏蔽搜索引擎”可额外保障其他主题／插件遵守Halo的noindex注入；两者不互相取消。
2. 你的实站已经使用Cloudflare。到其域名 **Security Settings → Bot traffic → Configure AI bot policies**，将 **Search、Agent设为Block，Training设为Disallow**，开启 **Bot Preference Sync** 并保存。界面／权限可能因计划变化，按当前控制台可用项设置；这一步不由主题开关自动执行。
3. 需要强制阻断时，在 **AI Crawl Control → Crawlers** 对已识别的训练／AI crawlers配置Block；补充WAF策略阻断不允许的自动化。Agent的robots声明与训练crawler的边缘拦截覆盖范围不同，不声称所有代理或伪装成人类的浏览器均可识别。只改User-Agent字符串匹配很容易绕过。
4. 不用Cloudflare管理robots时，将同目录的 **robots-禁止抓取.txt** 内容交给能管理域名根目录robots的Halo插件或反向代理，作为 **/robots.txt** 返回200与text/plain；不要放到文章、普通页面正文或主题assets里假装已生效。移除冲突Allow:/及更具体的允许组，检查CDN实际响应并清缓存。Content-Signal是扩展，基础Disallow:/才是通用拒绝抓取规则。

规则User-agent:*覆盖所有遵守robots的采集程序，包括Agents；没有通用的agents.txt或仓库AGENTS.md可以代替域名访问控制。TDM和自定义HTML拒绝文本只是使用偏好声明，不能承诺任何AI厂商都遵守。登录保护／服务器授权才适合必须不公开的内容；公开正文、RSS、公开API与图片链接仍可能被忽略规则的访问者读取。

**已有搜索结果**：Google需要先抓取才能读到noindex；如果立即Disallow:/，旧URL可能继续以无摘要形式留在索引。需要撤下旧结果时使用对应搜索站长工具的移除流程，并让其完成noindex重新抓取，再执行全面禁止抓取；没有自动撤回既有训练数据的能力。切勿把noindex写进robots.txt并期待它生效。

本轮只读取公开HTML／robots，没有登录或变更你的Cloudflare，也没有测试封禁效果。安装后检查最终HTML中robots标签、根目录robots实际规则和Cloudflare阻断日志；不能只看主题开关呈开启。

依据：

- [Halo主题SEO](https://docs.halo.run/developer-guide/theme/seo)：系统屏蔽时自动输出noindex。
- [Google noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing)：抓取与索引的差异。
- [Cloudflare robots政策](https://developers.cloudflare.com/bots/additional-configurations/managed-robots-txt/)：Search／Agent／Training、Bot Preference Sync和自愿遵循边界。
- [Cloudflare抓取控制](https://developers.cloudflare.com/ai-crawl-control/features/track-robots-txt/)：识别违规与crawler/WAF阻断。
