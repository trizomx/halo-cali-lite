## 0.2.0 的源码迁移

此前存在按默认 Tailwind 数值换算的问题。原项目在 `tailwind.config.cjs` 改写了字号、行高与 typography，本轮改为保留组件层级和原 utility class，提取参考站已编译的对应规则，而非继续逐条估算 CSS。

- 原始规则快照：`src/cali/upstream-utilities.css`，完整 SHA256、URL 与源文件校验记录见 `sources.json`。
- 自定义配置对照：`upstream-tailwind.config.cjs`，仅作来源记录，不执行 npm。
- 抽取器 `scripts/build-source.py` 保留被使用的规则、媒体查询、pseudo、dark 与 pulse 动画；限定在 `.cali-source` 下，禁止引入整个站点的全局重置。
- `preflight.css` 是限定作用域的必要基础重置；`bridge.css` 单独保存 Halo、无封面、等高和无障碍适配，便于区别源规则与改动。
- 生成的模板和脚本均标有 Generated；修改 `src/cali/` 后重新构建，不直接改生成文件。

当前抽取 248 个源 utility class，抽取主体约 35 KB（另有必要适配 CSS）。来源映射、保留参数和差异详见 `源码迁移对照.md`。这不是在 Halo 内运行 Next.js：React 组件改为 Thymeleaf，数据改由 Halo 提供，交互改为浏览器原生 API。

## 首页、文章卡片和布局

保留：全屏中性网格、顶部毛玻璃导航、14px/13px 导航字、1.5px 绿色指示线、页面加载后切换指示、逐像素滚动收起顶部栏。首页只有一个大头像，滚动或离开首页时缩入小头像位置；首页不输出头像旁站名，其余页静态显示名称。

容器断点继续按源 Container：<640px 两侧16px；640–1023px 两侧64px、最大672px；>=1024px 两侧112px、最大1024px。首页桌面左右两列均分，右侧内边距64px／xl80px；窄屏顺排。便签保留在首页右侧，订阅表单置于其下；“我的项目”纵向展示在首页右侧，替代“随便看看”；不再在页面下方重复展示。

首页近期文章标题复用源 PencilSwoosh 图标；归档页大标题同步按源字体配置修正。卡片由 `modules/posts :: card` 委托到源迁移片段，首页／归档／分类／标签／作者共用。保留源封面240:135、24px圆角、2px ring、分层背景图、主色70%覆盖层、向底部的主色渐变和8px backdrop-blur，悬浮时覆盖层降至30%。无封面或破图仍保留完整封面区，按文章标识生成稳定颜色；有图使用本地 Canvas 主色取样，跨域读像素失败保留图片并回退配色，不使用代理。

按源自定义行高修正：标题16px/28px、md20px/32px，固定两行56px/64px；信息区132px/130px。卡片总高为列宽×135/240＋信息区高，不因有图、无图或缺少分类而变成矮卡。保持日期、全部分类、真实浏览量和估算阅读时长，无真实数据时隐藏对应项。

每张文章列表卡片会读取一次 `postFinder.content(name)`，去除脚本、样式和标签后按300字符/分钟向上取整。这增加服务端正文读取，文章很多时需评估响应耗时；它不是实际阅读计时。

## 文章详情与加载

迁移 `BlogPostPage.tsx`、`BlogPostTableOfContents.tsx`、`blog/[slug]/loading.tsx`、Prose 与代码块结构。

- >=1024px 左目录160px、中间正文最大672px、右操作栏90px；窄屏隐藏两侧栏，正文完整保留。
- 封面240:135，md宽120%，圆角和模糊副本沿用源码；无封面用生成配色占位。模糊仅在封面范围，页面外层不裁切、不加左右遮罩。
- 标题32px/40px、sm48px/56px；正文16px/28px，保留源码段落、标题、引用、列表、表格和代码块排版。
- 封面、日期分类、标题、摘要、统计按源 spring 刚度／阻尼与0/.1/.2/.23/.255秒错峰入场；原生 WAAPI 数值积分近似，不能宣称与 Framer Motion 逐帧完全相同。
- H1–H6 目录保留原有 heading ID，无 ID 时生成唯一锚点；每项通过字号、字重、缩进及刻度分级，不再显示H数字标签。0.4.1改为v3文章地图，章节间距约52px，点击范围约41px；当前项拉长刻度并使用强调色，窄屏可展开浮动面板。
- 代码块保留 Halo 原有高亮 DOM，增加语言／文件名栏和复制按钮，不覆盖插件已有的 syntax token。剪贴板失败显示失败，不显示成功。需要安全上下文支持 Clipboard API。
- 右栏用真实阅读进度、复制链接、回顶替代原版云服务表情反应，不伪造点赞／访客数据。
- 点击文章链接后，超过120ms才显示源码 UFO pulse 提示；保留正常页面跳转。头像回退动画完成后也会触发。返回缓存页面、Esc或12秒超时会清除旧提示，避免遮挡卡住。
- 新页面正常渲染后分段入场；减少动态效果设置下静态展示。关闭 JavaScript 仍可阅读和导航。

原 Next.js Suspense 的流式路由不适用于原生 Halo，当前加载反馈是离开旧页面期间的渐进增强；没有引入全站 SPA 或伪进度条。尚未移植段落评论、表情、相关推荐、留言墙或云服务业务。

## 项目页面与首页展示

数据在 **主题设置 → 项目展示 → 项目列表** 管理，每项6个字段：名称、简介／技术说明、图标、HTTPS链接（可留空）、开始日期、结束日期。支持增删和排序，默认空列表，不添加测试项目。

首页右栏使用源 `app/(main)/Resume.tsx` 迁移的日志组件：圆图标外壳40px、内图32px、图文间距16px，项目名在首行，说明与日期在下一行；日期靠右，空间不足自然换行。配置的图标和描述继续沿用，未填开始日期就不显示日期；填了开始、没填结束才显示“至今”。栏目默认“开发日志”，已有用户保存的标题保持不变。首页展示前3项（可改）。

**独立项目页继续使用源 ProjectCard／Projects／Card 的卡片网格**，与首页Resume不是同一个组件。项目页展示全部配置项目，48px图标壳、36px图标、标题／简介／域名、1/2/3列及局部鼠标虚线效果仍保留。两处共用项目数据，不要求重复输入。

最简启用：新建并公开发布别名为 `projects` 的页面，保留默认模板即可。默认“自动识别项目页面”开关开启，主题识别该页面并自动用项目页布局和导航高亮。别名不同，在“手动指定项目页面”选择一次，无需再切模板。已有用户主动选择“项目”模板的页面也继续支持。实际链接从Halo permalink读取，不硬编码路径；页面未公开发布／已删除不会被当作导航目标。

主题不能凭空创建Halo页面路由；需要页面本身存在。自动发现最多检查前100个公开页面的元数据，超出范围或有多个候选时使用手动选择器。未发现有效项目页时隐藏项目入口，**不回退到首页锚点**。

## 两处邮件订阅

首页右侧和全站页脚各一处，复用迁移的 `Newsletter.tsx` 结构与样式，共用主题设置 **邮件订阅**。

- 可设置标题、说明、邮件服务的 HTML 表单 POST 地址、邮箱字段名（默认 `email`）。
- 小白用户优先填写“现成订阅页面地址”：按钮直接前往服务提供的订阅页面，本站不收集邮箱。若使用下方表单提交地址，地址必须是HTTPS、且服务应支持浏览器原生表单POST。访客提交后前往服务结果页，确认邮件、订阅存储、退订、反垃圾由该服务负责。
- 只提供原生单邮箱表单适配。若服务要求隐藏字段、验证码或JSON API，需要后续针对该服务实现；不能填写后台管理接口或私钥。
- 尚未提供服务地址时两处区块照常显示，邮箱和提交按钮禁用，并显示“邮件订阅尚未开放”。没有本地保存邮箱、伪成功、假订阅人数或假发送邮件。
- 本轮没有真实订阅服务配置，未发送邮件或提交任何个人邮箱。

原组件依赖 Drizzle数据库、邮件API与确认token路由，不能只复制到主题就获得服务端发送能力。需要接入实际服务后再验收邮件闭环。

## 后台设置：给小白用户的操作入口

主题设置现在分为7组、51个顶层设置项；项目列表另有6个字段，照片列表另有8个字段。所有开关默认保留当前设计，旧版本未保存的新选项也会回退到默认值。

| 分组 | 可以直接调整 |
| --- | --- |
| 首页与关于（9项） | 两行标题、简介、便签文案／栏目名／补充文字、便签开关、照片带开关与1–5张 |
| 照片页面（9项） | 内容开关、自动识别、可选手动指定页面、导航开关、电脑2/3/4列、预览尺寸、放大加载方式、信息开关、照片上传与排序 |
| 项目展示（7项） | 导航、首页日志开关、栏目标题、数量、自动识别、可选手动指定页面、项目列表（含图标、说明和可选起止日期） |
| 邮件订阅（8项） | 两处显示开关、按钮文字、现成订阅页链接、标题说明、表单提交地址与邮箱字段名 |
| 文章详情（7项） | 顶部封面、桌面目录、摘要、统计、阅读工具、分段入场和加载动画 |
| 背景与导航（7项） | 网格开关、浅／深色背景和强调色、桌面导航12–18px、指示线1–3px |
| 页脚（4项） | 补充文字、底部导航、GitHub入口、自动显示实际主题版本 |

操作顺序：上传安装包 → 若缺新选项先“重载主题配置” → 主题设置中保存 → 刷新前台。项目先发布页面后从下拉框选择；邮件先粘贴现成订阅页链接更容易接通。

背景颜色只接受6位十六进制，数值选项有限制和前台校验；不允许设置值注入任意CSS。外观配置在首次绘制前应用，明暗切换仍保留访客选择。手机导航固定13px，避免开启更多栏目后挤出屏幕；大字号可能减少桌面可用空间。

站点标题、Logo、favicon和首页文章数量继续在 Halo **系统设置** 管理，不重复设置；表单下方有操作提示。主题设置不要求编辑HTML、CSS或脚本。

## 构建、文件和交付

```text
src/cali/                 源码迁移组件、交互、原样式快照与哈希
scripts/build-source.py   抽取源 utility，生成运行模板／样式／脚本
templates/               原生外壳与页面，部分文件由构建生成
templates/modules/source-*  生成组件，禁止直接修改
templates/assets/cali-source.css  生成源样式
templates/assets/source-*.js      生成交互
templates/page_photos.html       独立照片页模板（完整内容区宽度）
templates/modules/gallery.html   照片瀑布流；v3布局与Halo适配
templates/assets/gallery.js/css  原生灯箱、v3瀑布流适配与入场样式
src/photos/              v3照片页来源、固定提交、哈希、相关快照及许可
settings.yaml            首页、项目、照片页面、订阅等7组配置
theme.yaml               身份、版本、项目页模板声明
docs/源码迁移对照.md      原组件到 Halo 的来源与差异
SOURCE-NOTICES.md         来源及第三方许可边界
package.py               构建＋安装包＋源码包＋解压目录
```

运行 `python3 scripts/build-source.py` 仅构建；运行 `python3 package.py` 构建并在 `dist/` 生成三个交付物。无需安装 npm/Node、React或原项目云服务依赖。源码交付只附当前安装包，不把历史 ZIP 当作维护目录。

安装包白名单：theme.yaml、settings.yaml、README、LICENSE、SOURCE-NOTICES、docs、templates、i18n。源码交付另含 src、scripts、AGENTS、package.py、.gitignore 和当前安装包。工作区 QA 的模拟文章、图标、Java依赖、日志、截图和脚本不会进入任何交付。

## 本轮验证与限制

- 140次 Spring6.2.2／Thymeleaf3.1.3 模板渲染：12个页面模板、2种公共布局调用，覆盖10种状态。使用 Halo 同类 JsonNode 与 JsonPropertyAccessor，检查空／有文章、缺失配置、null配置、无封面、站点头像、项目与订阅已配置、无效链接、所有栏目关闭、现成订阅页链接等。
- 检查首页恰好两处订阅、其他页一处；首页项目3项、项目页全部；项目读取永久链接，危险协议不生成外链；未配置订阅不收集邮箱。
- 保留原导航等待 load、逐像素顶部栏、头像共享过渡和稳定取色的隔离逻辑检查。
- 对新增目录、代码复制、阅读进度、spring动画／减少动态效果及加载生命周期执行隔离模型检查；JS语法、构建可重复性、ZIP白名单和完整性检查。
- 线上视觉参考页面可读；本地HTTP监听受沙箱限制，浏览器禁止file协议，因此本轮未完成真实浏览器像素／滚动验收，也未上传到完整 Halo 实例。140次本地模板渲染不能替代实站安装测试。

部署后重点检查首页卡片、无封面文章详情、长正文目录、手机导航、明暗模式、项目页面和邮件服务结果页。外部图片CORS、插件CSS和真实字体可能影响最终显示。当前安装包可直接用于更新查看效果，但不声称与参考站逐像素一致。

## 0.2.1：按源配色链路修复，并替换右侧栏目

### 先查源码

本轮复读 fork 与原作者 tag v2.0 的 `BlogPostCard.tsx`、`sanity/queries.ts`、`sanity/schemas/post.ts`、`ProjectCard.tsx`、`Projects.tsx`、首页和编译基础样式。原查询读取 `metadata.palette.dominant`；卡片使用其 background/foreground，不在前端做反相。Sanity 官方文档确认调色板包含图片主色、对比色及占比：https://www.sanity.io/docs/apis-and-sdks/image-metadata 。Halo封面没有这组Sanity元数据，因此本地取色仍是适配，不能宣称等同Sanity服务端算法。

### 可确定的问题与修复

1. 旧版 preflight 把 `::before/::after` 写进 `:where()` 参数；伪元素不能这样放入该选择器，导致 `--tw-content` 初始化无效。构建抽取器此前还漏掉了原 CSS 的 `:after,:before{--tw-content:""}` 基础规则，before/after工具类中的 content变量没有可用值。覆盖色层、底部渐变和backdrop模糊因此无法按源码生成。现在直接从源CSS抽取这条初始化并限定作用域，删除无效选择器。
2. 我此前在 `.source-card-info` 额外加了主色 background-color，源组件没有这层实色底。它与原 bg-blend-overlay 叠加会严重改变背景照片颜色，尤其是绿色；现在移除额外底色，保留原背景图＋before覆盖＋after渐变／模糊链路。没有对封面做 invert 或 hue-rotate。
3. 旧本地取色按封面中心裁切，并额外提高高饱和颜色的得分，与源查询使用整张资产调色板的意图不同。现在对整张图片按原比例缩到最长边64px、按每通道32步长RGB分箱（8×8×8）的像素占比选主色，不再奖励鲜艳颜色；黑白前景仍按亮度对比选择。忽略透明像素，保留缓存、CORS失败和破图回退。
4. 无图配色给文章标识的哈希增加最终混合，减少相似标识集中落在相邻色相。不同文章在色环内稳定变化，同一文章刷新／跨列表仍保持配色；不是每次刷新随机闪色，也没有全站固定紫色。JavaScript不可用时仍有nth-child的多色回退。

### 预览和原图策略

| 设置 | 首页 | 放大后 | 适用 |
| --- | --- | --- | --- |
| 手动查看原图（默认） | 懒加载预览 | 先显示1200px预览，访客点击才请求原图 | 大多数站点，控制流量 |
| 自动加载原图 | 懒加载预览 | 预览成功后，仅为当前查看照片请求原图 | 希望逐步清晰的站点 |
| 直接加载原图 | 懒加载预览 | 打开照片后直接请求原图，等待期间保留已有缩略预览 | 看重最高画质 |

自动模式遇到navigator.connection.saveData或2G时停留预览，访客仍可手动查看原图。切换／关闭会使旧请求结果失效，防止前一张的原图覆盖当前照片；不会预取整套原图。原图失败保留已加载预览并允许重试；加载较慢时有状态提示，无假进度条。

缩略图按官方 `thumbnail.gen(uri,size)` Finder 获取：s400px、m800px、l1200px。首页默认m，灯箱默认l；自定义预览图优先于自动生成。使用Halo原生附件选择器和array设置，不提供另一套上传后台，也不写云服务私钥。

**缩略服务的边界**：主题不在访客浏览器下载整张原图再声称“压缩省流量”，也不改变原文件或伪造压缩率。Halo缩略服务／存储策略需要能为图片提供对应缩略图；不支持的格式、外部地址或未启用的缩略能力可能返回原图或无法加载。此时可上传自定义小尺寸预览图，确保实际节省传输量。图片文件格式、缩略质量由Halo／存储服务负责；主题控制选择哪份图片和何时请求。`srcset`明确指向所选预览，避免浏览器悄悄升级为未选择的大图。

官方依据：https://docs.halo.run/developer-guide/theme/image-optimization （缩略Finder自2.19可用，目标仍>=2.27.0）；设置依据 https://docs.halo.run/developer-guide/form-schema ，使用array／attachment／select，不使用付费FormKit组件。

## 0.4.2：自动识别／手动指定的真正故障与实际版本显示

### 实站证据与根因

本轮直接以禁用缓存的公开GET读取 `/`、`/projects`、`/photos` 和公开SinglePage列表。资源版本确认实际运行 **0.4.1**；两页都返回200，但main仍是普通inner-page，没有gallery资源，照片导航缺失，项目链接仍为 `/#projects`。不是只看用户手写的页脚版本，也没有把问题归因于用户没开开关。

对照官方Halo **v2.27.0**源码：SinglePage.SinglePageSpec.visible的Java类型是 `Post.VisibleEnum`。SinglePageFinderImpl的getByName和list返回保持该类型的Vo；公开HTTP JSON把它序列化成字符串，所以前版用JSON重建的本地Map与真正模板运行时不同。

前版表达式 `spec.visible == 'PUBLIC'` 在运行时把枚举与字符串比较，结果为false。因此：

- 自动识别：published页面在publicPages筛选时被排除。
- 手动指定：getByName已经拿到正确页面，仍在projectsReady／photosReady处被同一个错误比较排除。**所以指定页面也一样失败。**
- 当前页分流：Ready为false，page.html无法选择项目／照片main，导航也无法生成正确链接。

本版所有相关判断统一使用 `#strings.toString(...visible) == 'PUBLIC'`，空值仍不能通过。保留发布状态、已删除、专用模板冲突校验和真实permalink，不把私密或草稿页面加入公开导航。

### 项目链接与后台

项目导航、页脚项目入口和首页日志“查看全部”只采用有效独立页面的permalink。取消所有运行模板中的 `/#projects` 回退；未找到有效项目页时不生成项目入口。有效已发布页面可以自动识别，也可手动选择，后者继续优先。

用户已有 `/projects`、`/photos` 和已上传的项目／照片无需重建或重传。安装更新后，原来的开关和手动指定继续保留；新增字段不覆盖已有数据。本轮未自动改动实站或用户后台。

### 页脚实际安装版本

**主题设置 → 页脚 → 显示实际主题版本号**，默认开启。公共页脚直接读取 `theme.spec.version`，例如本包显示 `cali lite v0.4.2`；自动更新，不取用户补充文字、旧缓存中的常量或JavaScript推测值。开关关闭时隐藏自动版本；“页脚补充文字”仍原样保留，用户之前手写的v0.4.1可自行删掉以免重复。新增开关后后台共7组51项，页脚4项。
