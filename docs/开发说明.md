## 1. 交付与安装

- `cali-lite-0.1.8.zip`：直接上传的 Halo 主题安装包，不需要解压后再压缩。
- `halo-cali-lite-source-0.1.8/`：同一版本的已解压可编辑源码，使用原生 HTML、CSS、JavaScript；不需要 Node 或前端构建服务。
- 源码包和安装包均附带本文档：`docs/开发说明.md`。
- 源码仓库：[trizomx/halo-cali-lite](https://github.com/trizomx/halo-cali-lite)。

目标版本为 **Halo 2.27.0 及以上**，`theme.yaml` 中使用 `spec.requires: ">=2.27.0"` 声明。0.1.2 已由用户确认在实际 Halo 站点正常运行；0.1.5 的新身份安装流程尚未实站验证。低版本没有验证，暂不声明支持。

安装步骤：

1. 进入 Halo Console → 主题 → 安装，上传 `cali-lite-0.1.8.zip`。
2. 选择内部标识为 `theme-cali-lite` 的“cali lite”，启用，打开站点首页。若从 0.1.4 及更早版本迁移，请先记录旧主题设置，再在新主题中重新填写；0.1.5 / 0.1.6 可直接更新当前主题。
3. 站点标题、Logo、副标题在 Halo 系统设置中调整。
4. 主题设置 → 首页与关于，可调整大标题两行、简介和侧栏短句。
5. 简介留空时使用站点副标题；没有 Logo 时显示主题自带的抽象符号。

文章、分类、标签和独立页面继续在 Halo Console 管理。主题不会创建文章、分类、用户、演示评论或其他测试记录。

## 2. 本次复刻范围

视觉方向参考 [cali.so v2.0](https://github.com/CaliCastle/cali.so/tree/v2.0) 与 [Oiov](https://www.oiov.dev/blog)，没有采用 Cali 最新 main 的架构或页面。当前主题源码仓库为 [trizomx/halo-cali-lite](https://github.com/trizomx/halo-cali-lite)。

本次重新编写模板、样式和脚本，主要保留：

- 中性浅灰白底色、居中内容区、全屏平铺细网格、局部绿色强调色。
- 首页单大头像，随下滑收缩至页头、回顶展开；两行标题、描边强调文字和简介。
- 首页封面文章预览卡片、右侧短句卡片，以及有封面时的倾斜照片带。
- 圆角卡片、简洁文章详情、明暗配色和手机布局。
- 顶部胶囊导航、毛玻璃和切换动效；导航指示在目标页面加载完成后移动。

没有复制原作者或 fork 中的个人头像、照片、正文、过时个人介绍、第三方付费模板文件、云服务逻辑或密钥。默认标题和空状态文案属于界面文案，不是测试文章数据。

### 顶部导航与外观按钮

| 按钮 | 简单功能 | 地址或数据来源 |
| --- | --- | --- |
| 首页 | 返回首页 | Halo 根路径 `/` |
| 文章 | 打开文章归档 | `site.routes.archivesUri` |
| 分类 | 打开分类集合 | `site.routes.categoriesUri` |
| 关于 | 原生弹窗，展示站点标题与简介 | 主题简介，留空使用系统副标题 |
| 外观 | 明暗切换、保存选择 | 浏览器 localStorage |

明暗切换按钮位于顶部导航右侧。第一次访问时跟随系统外观；用户手动选择后以手动设置为准。存储不可用时仍可在当前页面切换。关于弹窗支持关闭按钮、Esc 和点击外部关闭；浏览器原生 dialog 负责焦点管理。

本版没有做原 fork 的项目管理和留言墙业务，导航优先使用现成 Halo 页面。文章页提供简单的 H2/H3 目录锚点和回到顶部按钮。

## 3. 真实内容与空状态

首页直接使用 Halo 首页提供的 `posts.items`，没有在模板里写入文章数组或静态文章卡片。

照片带取当前首页文章列表前五项中有封面的文章，点击进入该文章。没有公开文章或前五项均无封面时，不显示照片带。它不是独立图库，也不会为了凑满五张而使用测试图片。

文章标题、摘要、日期、封面及分类来自 Halo 的文章变量。文章地址使用 `status.permalink`，分页使用 Halo 返回的 `prevUrl`、`nextUrl`、`hasPrevious()`、`hasNext()`。站点自定义文章路径后，无需改模板里的文章地址。

空站显示“下一篇记录，正在酝酿”等界面提示；没有分类／标签时显示集合空状态。正式 ZIP 中不包含测试用图片、预览 HTML、模拟数据、导入脚本或数据库内容。

## 4. 文件结构与修改入口

```text
halo-cali-lite/
├── theme.yaml                    # 身份、版本与兼容要求
├── settings.yaml                 # 四个主题设置项
├── i18n/default.properties       # 中文文案与默认消息
├── templates/
│   ├── layout.html              # Halo 标准 html(head, content) 布局契约
│   ├── modules/layout.html      # 内部公共外壳、顶部栏、关于弹窗
│   ├── modules/posts.html       # 文章卡片与分页片段
│   ├── index.html               # 首页
│   ├── archives.html            # 按年份的文章归档
│   ├── post.html                # 文章详情
│   ├── page.html                # 独立页面
│   ├── categories.html          # 分类集合
│   ├── category.html            # 单个分类的文章列表
│   ├── tags.html                # 标签集合
│   ├── tag.html                 # 单个标签的文章列表
│   ├── author.html              # 作者文章列表
│   ├── error/404.html           # 404
│   ├── error/error.html         # 通用错误页
│   └── assets/
│       ├── style.css            # 全部样式及响应式规则
│       ├── theme-init.js        # 首次绘制前应用明暗状态
│       ├── main.js              # 弹窗、切换、目录、回顶、年份
│       ├── navigation.js        # 导航指示、光晕、跨页位置与滚动反馈
│       └── avatar.js            # 单头像滚动收缩、跨页动画兼容回退
├── README.md
├── AGENTS.md                    # 本项目每次开发前必读约定
├── LICENSE
├── docs/开发说明.md            # 开发、打包与迁移说明
└── package.py                   # 本地打包工具，不放进安装 ZIP
```

这是直接维护 `templates/` 的原生主题，没有 Vite、Astro 或其他生成目录。可直接修改模板、CSS、JS；不涉及重建哈希资源。主题源码里的 `package.py` 只负责筛选和压缩文件，不生成页面。

在源码目录运行：

```bash
python3 package.py
```

脚本从 `theme.yaml` 读取版本，在 `dist/` 生成 `cali-lite-0.1.8.zip`。修改版本时需更新 `theme.yaml` 和文档；脚本自动生成相应文件名。安装包根目录直接放置 `theme.yaml`，没有多套一层文件夹。

样式关键值集中在 `style.css` 开头的 CSS 变量：`--surface`、`--accent`、`--line`、`--muted` 等。暗色变量位于 `:root[data-theme=dark]`。手机断点为 680px，中等屏幕断点为 900px；目录在不足 1280px 时隐藏，正文仍完整展示。

## 5. 对指定 AI 开发文档的落实

已阅读 [Halo AI 辅助](https://docs.halo.run/developer-guide/theme/ai)，并按索引读取本次使用的 Thymeleaf、页面变量、静态资源、主题设置和路由文档。

- 未使用 `#request`、`#response`、`#session`、`#servletContext` 或非公开请求上下文。
- 站点标题、Logo、副标题使用 `site`，不另设一套站点基础信息。
- 可配置路径读取 `site.routes`，文章／分类／标签链接读取对象 permalink。
- 主题资源使用 `@{/assets/...}`，附带主题版本参数。
- 没有重复输出系统自动注入的 description、keywords、favicon。
- 为保持范围简单，没有额外实现 canonical、Open Graph、JSON-LD。
- 保留 `<halo:footer />`，以便 Halo 系统页脚代码和插件注入。
- 标题、摘要和设置通过 `th:text` 输出。只有 Halo 已处理的文章和独立页面正文使用 `th:utext`。
- 可选主题分组通过 Halo JSON 属性访问器与空安全读取，缺少设置组或配置为空时仍有默认显示。

主要依据：[Thymeleaf](https://docs.halo.run/developer-guide/theme/thymeleaf)、[首页变量](https://docs.halo.run/developer-guide/theme/template-variables/home)、[文章变量](https://docs.halo.run/developer-guide/theme/template-variables/post)、[模板路由](https://docs.halo.run/developer-guide/theme/template-route-mapping)、[主题设置](https://docs.halo.run/developer-guide/theme/settings)、[静态资源](https://docs.halo.run/developer-guide/theme/static-resources)。

## 7. 本版刻意简化的部分

- 没有段落评论、普通评论组件适配、点赞、多表情、Newsletter、搜索、登录 UI、项目 CRUD 或留言墙。
- 分类集合先展示 Halo 提供的顶层分类，不递归展开子分类；分类内文章列表支持分页。
- 照片带不做图库排序配置；首页用真实文章封面，缩略图优化留待后续。

- 明暗模式依赖 JavaScript；关闭 JavaScript 时仍可正常阅读和点击站点页面，弹窗及外观按钮隐藏。

本次交付以快速查看视觉方向为目标。源码已在本地整理为 GitHub 仓库备份，尚未推送远端；没有访问或修改你的线上 Halo 数据。

## 9. 0.1.2：修复设置读取导致的模板异常，补齐布局契约

### 确定复现的问题

旧版本使用 `theme.config['home']?.get('headline')` 等表达式读取设置。但 Halo 的 `ThemeVo.config` 是 `JsonNode`，并接入 `JsonPropertyAccessor`。读取 `home` 后得到的包装对象不是普通 Map，不提供 `.get(String)` 方法，导致以下异常：

```text
EL1004E: Method call: Method get(java.lang.String) cannot be found on type
org.springframework.integration.json.JsonPropertyAccessor$ComparableJsonNode
```

异常在首页标题表达式处可复现；公共布局的简介也使用过相同写法，其他页面也可能受影响。修正为 Halo 支持的点号属性读取，例如：

```html
<span th:text="${theme.config?.home?.headline ?: '记录与思考，'}"></span>
```

本地先用旧模板和实际 JSON 访问器重现该异常，再以同一访问方式验证修正后的模板。无服务端日志，因此不能断言这就是线上唯一异常。

### 布局提醒的处理

[官方布局契约文档](https://docs.halo.run/developer-guide/theme/page-layout)说明：缺少 `templates/layout.html` 会让使用该契约的插件页面使用 fallback 布局，本身不会阻止安装、升级或启用。这与首页自身的模板异常是不同问题。

本版新增标准 `html(head, content)` 契约，保留内用布局于 `modules/layout.html`，公共外壳支持可选插件 head，避免重复 title。内用片段参数为 `html(viewContent, pageTitle, active, extraHead)`，避免和公共契约的 content 参数相互覆盖。

### 更新方式

0.1.2 当时沿用原主题身份，可直接更新；当前 0.1.5 已按要求更换主题身份，安装方式以本文第 1 节及第 12 节为准。文章无需重新导入。

若更新后仍返回 500，说明仍需检查其他运行时差异；可暂时切回原可用主题。此次对公开站点的只读请求返回了边缘 403（1010），未能读取该站点实际的 Halo 错误页面，也没有登录后台或修改线上状态。

源码依据：[Halo 2.27.0 ThemeVo](https://github.com/halo-dev/halo/blob/v2.27.0/application/src/main/java/run/halo/app/theme/finders/vo/ThemeVo.java)、[JSON 访问器注册](https://github.com/halo-dev/halo/blob/v2.27.0/application/src/main/java/run/halo/app/theme/dialect/EvaluationContextEnhancer.java)。


## 10. 0.1.3：cali lite，顶部毛玻璃导航与切换动效

用户已确认 0.1.2 在实际站点正常运行，并发布了测试文章。本次在该版本上修改导航展示，不改动内容模型和主题设置的读取方式。

视觉参考：[Oiov 笔记页](https://www.oiov.dev/blog)及旧版导航源码中的胶囊布局、背景模糊、鼠标光晕和活动项指示思路。没有复制站点内容或图片。

### 交互与样式

- 导航移入页头，桌面端居中，左侧站点 Logo／名称，右侧明暗切换。
- 页头滚动时保持顶部可见；胶囊使用半透明渐变、细边框、阴影，以及 18px 的 backdrop blur 和饱和度增强。
- 鼠标移动时在胶囊内产生低强度光晕，选中指示线在悬浮、键盘焦点和当前页面之间滑动。
- 关于弹窗打开时指向“关于”；关闭后恢复当前页面的指示。
- 普通同源导航保留 Halo 原生链接，通过 sessionStorage 暂存上一个活动项的几何位置，新页面的指示线由旧位置移动到当前项；数据过期、尺寸变化、存储被禁用时正常降级。

## 11. 0.1.4：导航完成加载后再切换指示线

修改后的时序为：点击导航链接 → 当前页面指示线保持原位 → 浏览器正常加载目标页面 → 目标页面触发 `window.load` → 指示线移动到新栏目。悬浮和键盘焦点只改变文字／光晕／焦点轮廓，不再提前切换活动指示。

- 导航依旧使用 Halo 的普通链接，没有拦截跳转、延迟网络请求或替换正文。
- 新页面加载过程中恢复上一页指示线的位置；页面加载完成后经过两个动画帧再启动移动。
- 位置记录绑定目标路径并校验时效和尺寸，避免其他页面或过期数据误用。
- 没有可恢复位置时，暂时隐藏指示线，加载完成后显示当前栏目。
- head 初始化脚本在待切换页面设置标记，避免新栏目的静态下划线在脚本初始化前提前闪现。
- 开启“减少动态效果”时同样等待加载完成，随后直接定位，不播放滑动动画。
- 关于弹窗不触发页面导航；打开成功后显示关于指示，关闭后恢复实际栏目。

此次隔离 DOM API 检查明确模拟了加载尚未结束、悬浮／聚焦、点击、触发 load 四个阶段，验证新指示线不会提前移动；同时验证了存储异常、目标不匹配、无旧位置与减少动态效果。它是逻辑检查，不替代真实浏览器视觉验收。

注意 `window.load` 会等待页面图片等常规资源；慢速资源会推迟指示线切换，这与本次“加载完成后再切换”的要求一致。

0.1.4 已实现以上导航时序，0.1.5 保留其功能。当前交付路径和安装方式见第 1 节；没有执行远端 GitHub 推送。
